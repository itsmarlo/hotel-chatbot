# Academic portfolio alignment

The supplied assignment's hotel task allows a fictional hotel and a ten-turn conversation. It
requires the assistant to ask for a guest name, stay period, and guest count. Bellhob keeps those
fields in `BookingState` and prevents a reservation until the guest confirms a valid quote.

| Development requirement | Evidence in this repository |
| --- | --- |
| Frameworks and tools set up | Pinned Python dependencies, Gradio UI, FastAPI, SQLite, FAISS, Docker |
| Diagram components implemented | Qwen JSON proposal, deterministic state and date check, policy RAG, guarded booking tools, clarification and Gradio reply |
| Code commented | Module and function docstrings plus comments at model and booking trust boundaries |
| Training data collected | Authored synthetic intent, BIO slot and policy evaluation files with provenance notes |
| NLP models trained | Reproducible intent and BIO training script, saved artifacts and evaluation JSON |
| Iterative optimization | Development-set comparison of word, character and embedding models; RAG and dialogue checks; single-prompt baseline comparison |

The development presentation is generated by `scripts/build_development_presentation.py` after
the comparison metrics have been recorded. It contains ten slides and clickable framework links.
The model outputs and all test prompts are synthetic. This is an academic demonstration, not a
real hotel reservation service. The finalization phase's tutor feedback, abstract and upload
package are separate submission steps.
